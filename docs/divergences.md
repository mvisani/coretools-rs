# Divergence log

Behavioural differences between coretools-rs and C++ [wegmannlab/coretools](https://bitbucket.org/wegmannlab/coretools) at commit `126744e`. Every entry is pinned by a Rust test. API reshaping without a behavioural effect (traits instead of implicit conversions, `Result` instead of exceptions for user errors) is not listed; see ADR-0001.

| C++ unit | old behaviour | new behaviour | reason | Rust test |
|---|---|---|---|---|
| `TConverter<phred>::from<hpPhred>` | Floors: `t/100` is integer division, so HpPhred 699 → Phred 6 and 150 → 1. | Rounds to nearest: 699 → 7, 150 → 2. | Every other conversion to Phred rounds; flooring biased HpPhred → Phred towards higher probabilities. | `probability::tests::hp_phred_to_phred_rounds_to_nearest` |
| `TConverter<phred>` / `TConverter<hpPhred>` from Linear, Log, Log10 | Negative or NaN Phred scores (Linear input above 1, NaN input) are cast to an unsigned integer: undefined behaviour. | Map to 0, the highest probability. | Remove undefined behaviour. | `probability::tests::conversions_to_phred_saturate` |
| `TSomeProbability(value)` | Range check only when compiled with `CHECK_INTERVALS` (off by default); otherwise out-of-range values are accepted silently. | `Probability::new` always checks and returns `ProbabilityError::OutOfRange`; `new_unchecked` skips the check. | Invalid input must be caught where it enters, independent of build flags. | `probability::tests::linear_probability`, `probability::tests::log_probability`, `probability::tests::log10_probability` |
| `TSomeProbability::getAsTag` | On a value that is not a tag, asserts only with `CHECK_INTERVALS`; otherwise returns an arbitrary byte. | `byte_tag` returns `None`. | A non-tag has no byte to decode. | `probability::tests::byte_tags` |
| `TSomeProbability::setAsTag(char)` | Where `char` is signed (x86, Apple arm64), bytes 128–255 are negative and encode to values that are not tags (Linear byte 255 → 0) or decode to a different byte. | `set_as_byte_tag` takes a `u8`; every byte 0–255 encodes to a tag and decodes back to itself. | Byte tags must round-trip. | `probability::tests::byte_tags_above_127_round_trip` |
| `operator+` / `operator+=` on `PhredInt`, `HPPhredInt` | Wraps around on overflow: `PhredInt(200) + PhredInt(100)` is 44, a far higher probability; `HPPhredInt(65534) + HPPhredInt(1)` is the tag value. | Saturates at the representation's maximum (the lowest probability, never the HpPhred tag). | A product of probabilities cannot become more probable; matches the saturation of conversions. | `probability::tests::adding_phred_probabilities_saturates_at_the_lowest_probability` |
| `average(TConstView<Probability>)` | An empty view divides by zero and returns NaN. | `Probability::average` returns `None`. | NaN is not a probability. | `probability::tests::average_stays_in_the_same_representation` |
| `fromChar` (probability.h) | Where `char` is signed (x86, Apple arm64), bytes 128–255 are negative and clamp to `!` (Phred 0); where it is unsigned (ARM Linux) they clamp to `~`. | `PhredProbability::from_ascii` takes a `u8`; bytes above `~` clamp to `~` (Phred 93) on every platform. | Clamp by byte value, consistently at both ends of `33..=126`. | `probability::tests::phred_ascii_base_quality_clamps` |
| `WeakType(value)`, `WeakType::operator=(value)` | Interval checked only in debug builds or with `CHECK_INTERVALS`; release builds accept any value. | `Bounded::new` and `FromStr` always check and return `BoundedError::OutOfInterval` naming the interval; `new_unchecked` checks in debug builds only. | Invalid input must be caught where it enters, independent of build flags. | `bounded::tests::checked_construction_names_the_interval`, `bounded::tests::each_interval_admits_exactly_its_finite_values` |
| `intervals::StrictlyPositive`, `StrictlyNegative`, `ZeroOneOpen`, `ZeroOpenOneClosed` on `double` | The open end at 0 is `numeric_limits<double>::min()` (2.2e-308, the smallest normal), so subnormal values such as 1e-310 are rejected. | Every value above (below) 0 is admitted; the end is the smallest subnormal, 4.9e-324. | Subnormals are strictly positive; `smallestPositiveRepresentableNumber` did not return the smallest positive number. | `bounded::tests::open_float_ends_exclude_only_the_end_point` |
| `WeakType<double, …>` arithmetic with `*NoCheck` skills | The result is never checked: two `ZeroOneOpen(1e-200)` multiply to a `ZeroOneOpen` holding 0. | Float arithmetic that returns a `Bounded` value checks its result in debug builds, so overflow, underflow or division by zero leaving the interval panics there; release builds still store the result unchecked. | Same contract as `new_unchecked`; interval violations surface in tests. | `bounded::tests::closed_arithmetic_leaving_the_interval_numerically_is_a_dev_error` |
| `StrictlyPositiveUInt` `operator+`, `operator*`, `+=`, `*=` (`AddableNoCheck`, `MultiplicableNoCheck`) | Overflow wraps silently in every build: `max + 1` is a `StrictlyPositiveUInt` holding 0. | Overflow panics in every build, as it already did for `UnsignedInt8`…`UnsignedInt64` (`*Check` skills). | A wrapped integer is far from the true result and can leave the interval. | `bounded::tests::strictly_positive_uint_overflow_is_a_dev_error` |
| `UnsignedInt8`…`UnsignedInt64` `operator/`, `/=` (`DivisibleCheck`) | Division by zero: undefined behaviour. | Panics (`attempt to divide by zero`) in every build. | Remove undefined behaviour. | `bounded::tests::unsigned_division_by_zero_is_a_dev_error` |
| `StrictlyPositiveUInt` / `StrictlyPositiveInt` `operator/` (`DivisibleNoCheck`) | Integer division rounding to 0 yields a strictly positive value holding 0. | Division of two `StrictlyPositive` integers returns the raw integer. | Integer division can leave `(0, max]`. | `bounded::tests::strictly_positive_uint_division_returns_the_raw_number` |
| `skills::MultiplicableCheck::check_u_int` (unsigned `operator*`, `operator*=`) | Checks overflow as `Second <= max / First`, which divides by zero when the first operand is 0: undefined behaviour (crash on x86). | Overflow is detected with `checked_mul`; `0 * x` is 0. | Remove undefined behaviour. | `bounded::tests::unsigned_multiplication_by_zero_is_zero` |
| `operator<<(ostream, WeakType)` on floating types | Prints 6 significant digits: 0.1234567 → `0.123457`. | `Display` prints the shortest representation that parses back to the same value. | Printed values must round-trip. | `bounded::tests::display_prints_the_shortest_round_trip_representation` |
| `TNumericRange::rangeString` | Prints bounds with 6 significant digits, so re-parsing can change them (`[0.1234567,1]` → `[0.123457,1]`). | `Display` prints the shortest representation of each bound; `range.to_string().parse()` returns the same range. | The printed range must read back as the same range. | `bounded::range::tests::display_round_trips_every_bound` |
| `TNumericRange(T Min, bool, T Max, bool)` / `set(T, bool, T, bool)` | Accepts infinite ends, which `rangeString` prints as `-inf` / `inf` and which then read back as the type's finite extremes: a different range. | `NumericRange::new` rejects ends beyond the type's extremes (infinities, NaN) with `BoundedError::OutOfInterval`, as parsing already did. | Every range must print and read back as itself. | `bounded::range::tests::ends_beyond_the_type_extremes_are_rejected` |
| `TNumericRange(std::string_view)` / `set(std::string_view)` | An empty or whitespace-only string reads `front()` of an empty view: undefined behaviour. | `BoundedError::InvalidRange`. | Remove undefined behaviour. | `bounded::range::tests::parse_rejects_an_empty_string` |
| `TNumericRange::within` | NaN is neither `smaller` nor `larger`, so `within(NaN)` is true for every range. | `contains(NaN)`, `is_below(NaN)` and `is_above(NaN)` are false. | NaN lies in no range. | `bounded::range::tests::nan_lies_neither_within_nor_outside_a_range` |
| `TTrigamma::trigamma` | The asymptotic series has `1/(6x⁴)` where the `1/(6x³)` term belongs and stops after it: ψ₁(6) is 0.18068 instead of 0.18132 (relative error 3.5e-3). Arguments below -2^53 loop forever. | The full series to B₁₄ after shifting to x ≥ 10, reflection for x < 0, `+inf` at the poles; matches mpmath to 1e-9. | Wrong values. | `special::tests::trigamma_matches_mpmath` |
| `TDigamma::digamma` | For x ≤ -249 the `uint8_t` shift counter wraps around and the loop never ends. | `digamma` (statrs) uses the reflection formula. | Terminate with the right value. | `special::tests::digamma_of_large_negative_arguments_terminates` |
| `TFactorial::factorial` | n > 170 throws (`DEV_ASSERT`). | `factorial` (statrs) returns `+inf`. | statrs; an overflowing `f64` product is `inf`. | `special::tests::factorial_beyond_170_overflows_to_infinity` |
| `choose`, `chooseLog` | k > n: `n - k` is negative or wraps around, so `factorial` / `factorialLog` throw or evaluate `gammaLog` of a huge number. `choose` throws for n > 170 (`factorial`) and converts results beyond 2^64 to `size_t`: undefined behaviour. | `binomial` (statrs) returns 0 and `ln_binomial` `-inf` for k > n; `binomial` is an `f64` for every n (`binomial(200, 2)` is 19900). | There is no way to choose more than n; remove undefined behaviour. | `special::tests::choosing_more_than_n_has_no_way`, `special::tests::binomial_coefficients_go_beyond_170_and_u64` |
| `TIncompleteGamma::lower`, `upper` | x = `inf` gives NaN. a = 0 gives the limits 1 and 0; a < 0 or x < 0 give meaningless values or NaN. | `lower_incomplete_gamma` / `upper_incomplete_gamma` give 1 / 0 at x = `inf`; a ≤ 0, a = `inf` or x < 0 panic. | Limits at the ends of x; invalid parameters are dev errors. | `special::tests::incomplete_gamma_is_total_at_the_ends_of_x`, `special::tests::incomplete_gamma_of_negative_x_is_a_dev_error`, `special::tests::incomplete_gamma_of_non_positive_a_is_a_dev_error` |
| `TBinomPValue::binomPValue(k, l)` | P(X ≤ min(k, l)) for X ~ Bin(l, ½), but for k + l < 100 a lookup table makes it X ~ Bin(max(k, l), ½): (10, 2) gives 0.0547 although 10 successes exceed 2 trials. `ln ½` is rounded to 7 digits (relative error ~2e-6 at 100 trials). | `binomial_p_value(successes, trials)` is P(X ≤ successes) for X ~ Bin(trials, ½), 1 when successes ≥ trials, accurate to 1e-9. | One definition for all arguments, matching the C++ test values. | `special::tests::binomial_p_value_is_the_lower_tail_under_one_half`, `special::tests::binomial_p_value_of_k_at_least_n_is_one` |
| `TKolmogorovSmirnovDistr` (all four functions) | Evaluate `sqrt(z)` (and `sqrt` of the inverse's terms) where Numerical Recipes squares, so every value except at z = 1 is wrong: P(0.5) is 0.52 instead of 0.036. The inverse throws at q = 0. | `kolmogorov_smirnov::{cdf, sf, inverse_cdf, inverse_sf}` square as in Numerical Recipes and match the Kolmogorov series to 1e-9; `inverse_sf(0)` is `inf`. | Wrong values. | `special::kolmogorov_smirnov::tests::cdf_and_sf_match_the_series`, `special::kolmogorov_smirnov::tests::inverses_invert_the_distribution` |
| `runOneSampleKolmogorovSmirnovTest` | Compares each reference CDF value with the empirical CDF after the step of the largest distance so far instead of the previous step, overstating D (uniform data 0, 0.5, 0.99: 0.657 instead of 1/3); the p-value inherits the error above. | `TDynamicBinnedSumLog::add` (`TSumLog<>`, `TSumLogProbability`) | Multiplies subnormal values into the product unnormalised, losing significant digits (1.3 · 3e-320 keeps about 4). 0 fails a debug assertion; two negative values cancel to a finite sum. | `DynamicSumLog` splits every value into mantissa and exponent, so subnormal values keep full precision; 0, infinite, negative and NaN values give the naive sum's `-inf`, `inf` or NaN. | Match the naive sum for every input. | `special::sum_log::tests::dynamic_bins_keep_the_precision_of_subnormal_values`, `special::sum_log::tests::dynamic_bins_follow_the_naive_sum_through_zero_infinity_and_negatives` |
| `TAccept::accept`, `TAcceptOddsRatio::accept` | Each lookup bound is the `ln` / `logit` of a bin edge rounded to 11 decimals; where it rounds below the exact value, draws within ~1e-11 below that edge are accepted although `ln u > ln q` (48 of 100 edges for `TAccept`).
